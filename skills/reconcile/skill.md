# /reconcile: land a branch on the integration trunk

Contract: `docs/contract-reference.md` BR-10. Run one landing at a time per repo.

1. **Model.** `git show origin/<trunk>:.reconcile-gate.json` is exactly `{"model":"single-trunk"}`: dispatch `aa_reconciler` and stop here. Otherwise the integration trunk is `dev`, else `develop`; neither exists: STOP and ask, never create one.
2. **Preconditions.** Independent code review (§CR) has no open blocking finding. For an issue, its owner-maintained phase map covers every criterion exactly once. Do not audit against a candidate that will still be rebased or amended; final review and readiness happen after the candidate and base SHAs are fixed. A full audit PASS is post-land only.
3. **Use only the assigned checkout and acquire the lock.** The originating issue or dispatch must name the exact checkout and working branch. Record the checkout path, branch, HEAD, and `git status --porcelain`; proceed only when the branch matches and the tree is clean. Do not select a different clean-looking checkout or move another agent's/session's HEAD. If the assigned checkout is dirty, ownership is unclear, or the expected branch is absent, stop and report its exact state. Run `scripts/reconcile_lock.sh acquire <task-id> <assigned-checkout> <assigned-branch>` from that checkout before changing HEAD; the command verifies the current path and branch match the assignment. If acquisition fails or lock state is malformed, stale, or unknown, stop without clearing it. Release with `scripts/reconcile_lock.sh release <task-id> <assigned-checkout> <assigned-branch>` after success or failure. Release refuses a lock owned by another host because its process liveness cannot be checked here. Lock reads and owner removal use a pinned no-follow directory descriptor; the lock serializes reconciliation but does not authenticate the prompt author. Do not automatically run `git worktree add`. A new checkout is allowed only after an explicit owner request and the shared guard verifies linked-worktree count below the hard cap of five plus every other checkout clean and landed on the verified policy trunk. If remote, policy, or checkout state is uncertain, preserve work and inspect read-only; do not create a checkout or invoke `/reconcile`. Before rewriting anything, tag the tip `backup/reconcile-<branch>`.
4. **Rebase** onto `origin/<integration>`. A conflict you do not fully understand: STOP and report the files. Never `-X theirs/ours` to get through it.
5. **Squash** to one commit: `git reset --soft origin/<integration> && git commit` with the branch's purpose as the message.
6. **Gate and audit** the exact candidate commit, using the repo's instruction files. Red: STOP. If `tools/suite_lane.py` exists, run `python tools/suite_lane.py run --base <integration sha> --trailer-out <file>` and append the trailer with `git commit --amend`. After the final amend, run independent review and have a fresh auditor return `READY_TO_RECONCILE` for all PRE_LAND criteria. Validate with `python scripts/validate_reconcile_evidence.py legacy --repo <owner/repo> --issue <id> --repo-root <assigned-checkout> --integration-ref origin/<integration>`; it must match current candidate/base SHAs. Any amend or rebase invalidates prior review/readiness. PR flow validates with the `pr --repo <owner/repo> --issue <id> --pr <number>` subcommand.
7. **Push** `git push origin HEAD:refs/heads/<integration>`, never forced, so a moved trunk is refused. If refused, keep the lock; fetch, rebase, squash, rerun the exact-commit gate, independent review, readiness audit, and validator against the new SHAs without reacquiring the lock. Retry the push once. If the second push is refused or any gate fails, release the lock and STOP with the exact blocker. Never skip hooks.
8. **Verify, release, and final-audit.** Fetch and verify `git merge-base --is-ancestor HEAD origin/<integration>`; record the landed SHA. Release the lock on every normal success or failure path. Then dispatch a fresh auditor for every issue criterion against that landed SHA and run `python scripts/validate_reconcile_evidence.py final --repo <owner/repo> --issue <id> --repo-root <assigned-checkout> --integration-ref origin/<integration>`. Record final PASS on the originating issue (the canonical final-audit record for both flows); a PR may link to it. Require a fresh full-issue PASS before closure. If final audit fails, fix on the same issue branch and repeat the reviewed readiness/reconcile flow. **Interrupted-lock recovery:** inspect `scripts/reconcile_lock.sh status` and verify no reconcile process is active for this checkout. Release only when the recorded task, checkout, and branch match this assignment, using `scripts/reconcile_lock.sh release <task-id> <assigned-checkout> <assigned-branch>`; malformed or mismatched state means stop and preserve it. Never remove lock files manually or clear by age/PID alone. Keep the branch and backup tag unless the operator says otherwise.

Never push to the production trunk, use `--admin`, or open a feature PR from this flow.
